# Интерфейс SmartFridge

## Область реализации

Оболочка приложения после входа: навигация, профиль, настройки, оформление подписки и страницы будущих функций. Регистрация сохраняет последовательность: подтверждение почты → выбор плана → оформление → /home. Учёт продуктов, рецепты, ИИ, приглашения и управление устройством не реализованы. В интерфейсе нет вымышленных запасов, температур и показателей экономии.

## Визуальная система

Цвета наследуются из общих style.css и theme.css, как у index, входа и подписок. Светлая тема: фон #F4F7F2, поверхности #FFFFFF, текст #1B302C, зелёный #305D48. Тёмная: фон #191F1C, поверхности #222A25, текст #D1DBD2, акцент #A4BF9E. Выделение текста в тёмной теме: #405D4B с текстом #F1F5EF.

Локальный Onest с кириллицей, прямые углы, компактные рабочие элементы. Главная: отдельная область хранения и модули с векторными рисунками, приглушёнными акцентами и прямыми переходами. «Добавить продукт» находится внутри холодильников. Компактная закрытая карточка содержит только название и замок.

Референсы использованы для структуры и визуальной сдержанности: Steep, Seline, Control AI, Shopeers, Limón. Полные изображения Dribbble недоступны; по ним использовались только подтверждённые описания и палитры. Рисунки в workspace_graphics.html декоративные, без фиктивных данных.

## Навигация

На компьютере меню сворачивается до значков с сохранением состояния. Отдельные кнопки раскрывают подразделы; текущий подсвечен. Полоса прокрутки скрыта, сама прокрутка сохранена для длинного меню. На телефоне открывается модальная навигация. Профиль и настройки — отдельные кнопки в общей шапке, рядом тема и уведомления. Выход находится в настройках.

Поиск по меню — второстепенное действие и Ctrl/Cmd+K, без запросов к ИИ. На внутренних страницах есть явная ссылка «Назад» в родительский раздел; из подписки — в настройки. Ссылки работают без JavaScript.

Описания открываются в модальном диалоге: название, несколько абзацев, закрытие кнопкой/Escape, возврат фокуса. Кнопки описаний можно скрыть в настройках. Тема, состояние меню и видимость описаний сохраняются в браузере. Анимации раскрытия и диалогов учитывают prefers-reduced-motion.

## Доступ по тарифу

Единая политика в services/workspace.py формирует карточки, боковое меню, результаты поиска и проверки прямых URL. Доступ определяется действующим планом из БД при каждом запросе.

| Возможность | Требуемая подписка |
| --- | --- |
| Семья, приглашения, общий доступ и совместные покупки | Семейная базовая / Семейная премиум |
| Генерация рецептов, персональное меню, чат и помощь ИИ с готовкой | Премиум / Семейная премиум |
| Учёт продуктов, обычные рецепты, дневник, статистика, справка и базовые голосовые сценарии | Любой действующий план |

Недоступные разделы не содержат подразделов. Нажатие на замок/название открывает условия доступа и ссылку на тарифы. Прямой URL возвращает HTTP 403 с условиями. JS не выдаёт права. Смена плана, понижение и окончание периода учитываются на следующем запросе. Без активного плана остаются доступны общие настройки и оформление подписки.

/settings — общие настройки, /settings/subscription — подписка. Пробная неделя доступна только личной базе; семейная база и премиум не получают пробу. Локальная оплата остаётся симуляцией.

## Проверки перед публикацией

На временной БД проверены 39 страниц оболочки и доступ к маршрутам во всех четырёх планах. Пройден путь регистрации с замоканной отправкой письма, подтверждения, обязательного плана, локальной оплаты, повышения/понижения, входа и выхода. SMTP и внешние банковские сервисы при проверках не вызываются.

Проверены размеры от 320 px, обе темы, состояния замков, диалоги, клавиатура, сворачивание меню, прямые переходы и поиск. Автоматический аудит доступности основных страниц приложения, входа, подписок и открытых диалогов не выявил ошибок. Самостоятельный HTML используется только для предпросмотра и не заменяет шаблоны Flask.


## Места хранения

Реализован личный CRUD в /home/fridges/storage. Список с поиском по названию/расположению, фильтром типа и 12 записями на страницу; пустые состояния. Создание, карточка, редактирование и отдельное подтверждение удаления. Поля: уникальное в пределах владельца название, тип, необязательные расположение и заметка. Сохранение в storage_locations; остальные модели не меняются.

Только владелец и только действующая подписка. Токен формы, POST для изменений, проверка версии против устаревших форм. Формы предупреждают о несохранённых изменениях. Удаление необратимо и требует галочки. Продукты, семейный доступ, датчики и уведомления не добавлены. Проверки: изолированная БД, чужие записи, CSRF, конфликты обновления/удаления, дубликаты, XSS, подписки, поиск/фильтры/страницы и реальный браузерный сценарий CRUD. Для шести состояний проверены четыре ширины и две темы.
